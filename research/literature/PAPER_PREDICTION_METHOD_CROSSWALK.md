## Interpretation rules

1. “Method identified” means the paper text describes or uses the method; it does not mean this repository has re-run it.
2. Paper-reported performance is not a project result. A project status of `TESTED` requires an immutable NIFTY result artifact and a passing independent tester report.
3. Where a paper predicts price, evaluate price regression separately from direction. A direction derived from a price forecast is `UP` only if forecast close exceeds decision-time close, `DOWN` if lower, and `FLAT` if equal within the pre-registered tolerance. Do not compare price RMSE directly with direction AUC.
4. Preserve each paper’s native horizon as a supplemental task where specified, but use chronological point-in-time evaluation as the common comparison. Do not reproduce random shuffles or full-sample feature selection as the primary result if they leak future information.
5. “No data found” is not an acceptable shortcut. Attempt eligible free sources first, record source/coverage/missingness, and use `BLOCKED_DATA` only after the documented source gate fails.
6. Papers about option strategies without an explicit NIFTY forecast model remain tagged `STRATEGY_ONLY`; their option P&L is not included in this prediction-only phase. CCI may be tested as a directional signal adaptation only after protocol amendment and tester approval.

## Complete paper-replication status policy

Use one of the following statuses per **paper × method × feature pipeline × horizon** row:

- `TESTED_AND_AUDITED`: immutable project result artifact and independent tester PASS both exist.
- `TESTED_NEGATIVE`: completed and independently audited; no significant/credible predictive value under the frozen criteria.
- `BLOCKED_DATA`: required field fails the documented free-source/point-in-time/coverage gate.
- `BLOCKED_METHOD`: published method is too under-specified or cannot be implemented faithfully with the available dependencies; precise missing elements and feasible alternatives are documented.
- `REJECTED_AT_GATE`: tester rejected the exact implementation/protocol; keep the attempt as non-evidence.
- `NOT_YET_REVIEWED`: extraction or mapping is incomplete; never describe it as tested.

## Common evaluation controls

- Shared target labels: future close-to-close return sign for horizons 1, 2, 3, 5 and 10 sessions; FLAT is handled with a frozen numerical tolerance. Paper-native 30-session targets are supplemental where expressly described.
- Primary direction metrics: ROC AUC, PR AUC, Brier score, log loss, balanced accuracy, sensitivity, specificity and calibration; give sample count and class prevalence for every cell.
- Price-regression metrics: MAE, RMSE and R², with direction derived and evaluated separately.
- Baselines: causal historical-rate probability, persistence/previous-direction, plus 50/50 random baseline where mathematically appropriate.
- Point-in-time: all feature values and transformations at timestamp t must be available by the decision cutoff at t; every training label must end before the forecast decision; scaling, feature selection, tuning and probability calibration fit on training rows only.
- Statistical control: paired evaluation rows; block bootstrap for dependent time series; one declared familywise maximum-statistic test over the pre-registered paper-method × horizon grid, with multiplicity correction and effect sizes / confidence intervals. The existing final holdout remains sealed.
- All method failures, unavailable inputs and zero-sample cells must be retained in the results grid with a reason code, not silently dropped.
